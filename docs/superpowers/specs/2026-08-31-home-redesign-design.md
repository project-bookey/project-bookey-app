# 홈 화면 OTT 리디자인 — 설계 문서

2026-08-31 · 브레인스토밍 세션에서 사용자와 함께 결정
전제: [디자인 토큰 스펙](2026-08-31-design-tokens-design.md) — 다크 기본, 틸 악센트, 블랙 크롬, Pretendard.

## 목표

홈 탭을 OTT 문법(대형 히어로 + 가로 표지 행)으로 다시 만든다. 기존 홈(인사·재촉 배너·
세로 카드 목록·알림)을 대체하며, 이 화면이 레거시 호환 레이어를 쓰지 않는 첫 화면이 된다.

## 결정 요약

| 항목 | 결정 |
|---|---|
| 히어로 | 풀블리드 — 표지를 배경으로 깔고 스크림 위에 정보·CTA (시각 비교로 A안 선택) |
| 이벤트 배너 | 카드 캐러셀 (가로 스와이프 + 페이지 인디케이터, B안 선택) |
| 행 구성 | 이벤트 배너 → 히어로(이어 읽기) → 읽는 중 → 읽고 싶은 → 추천 → 인기 |
| 인기 정의 | 전체 사용자 서재에 담긴 수 집계 순 |
| 추천 정의 | 에디터 픽 — 운영자 큐레이션 (백오피스에서 관리) |
| 기존 블록 | 스트릭·오늘 독서 = 히어로 아래 한 줄 요약 · 재촉 = 히어로가 밀린 책 우선 노출 · 알림 = 헤더 종 아이콘 → `/notifications` |
| API 형태 | 리소스별 엔드포인트 (홈 애그리게이트 없음) |
| 데이터 없는 블록 | 백엔드 API 신규 개발 병행 (배너·인기·추천) |

## 화면 구성 (위→아래)

1. **헤더** — 기존 블랙 크롬 + 로고 홈 버튼 유지. 우측에 종 아이콘 추가(미열람 수 배지).
   누르면 새 서브 화면 `/notifications`(기존 `notificationApi.list` 기반 간단 리스트, 항목
   탭 시 `open` 호출) 이동. 홈 본문의 알림 블록은 제거.
2. **이벤트 배너 캐러셀** — 가로 페이징 스와이프 + 하단 페이지 인디케이터.
   `GET /api/v1/banners` 결과(기간 내 활성, sortOrder 순)를 카드로. `imageUrl` 있으면 이미지
   배경, 없으면 `bgColor` 단색 배경 + 텍스트. 탭 시 `linkUrl` 이동 — `http(s)://`로 시작하면
   외부 브라우저, 그 외(`/club/join` 등)는 앱 내 라우트로 해석. 0건이면 영역 숨김.
3. **풀블리드 히어로 (이어 읽기)** — 대상 책 표지를 확대(cover)·블러해 배경으로, 하단→투명
   스크림(`colors.scrimStops`, `expo-linear-gradient` 이 시점에 의존성 추가) 위에
   아이브로우("이어 읽기")·제목·저자·진행(쪽수/%)·진행 바·"▶ 이어서 읽기" CTA(→ `/timer?recordId=`).
   보조 버튼 "상세"(→ 도서 상세).
   **대상 선정**: READING 중 `lagLevel`이 가장 심각한 책 → 전부 정상이면 `lastReadAt` 최신 책.
   기존 재촉 배너의 역할을 히어로가 흡수한다.
   히어로 바로 아래 한 줄 스트릭 요약: "N일 연속 · 오늘 M분" (`statsApi.summary`).
4. **표지 행 4개** — 공용 `BookRow` 컴포넌트:
   - **읽는 중**: 표지 하단에 진행률 미니 바 오버레이. 탭 → 도서 상세. "전체보기" → 서재 탭.
   - **읽고 싶은**: WANT_TO_READ 목록. "전체보기" → 서재 탭.
   - **추천**: `GET /api/v1/books/recommended`. 탭 → 도서 상세.
   - **인기**: `GET /api/v1/books/popular`. 순위 뱃지(1·2·3…) 표시. 탭 → 도서 상세.
5. **빈 서재 상태** — READING 0권이면 히어로가 온보딩 배너("첫 책을 찾아보세요" + 검색 CTA)로
   대체. 각 행은 일반 규칙(빈 = 행 숨김)을 따르므로 읽고 싶은 책이 있으면 그 행은 그대로
   보이고, 추천·인기 행이 콘텐츠 발견을 담당.

## 컴포넌트 · 파일

```
app/(tabs)/home.tsx          전면 재작성 — 행 조립만 담당
app/notifications.tsx        새 서브 화면 (알림 리스트)
src/components/home/
├─ BannerCarousel.tsx        이벤트 배너 캐러셀
├─ HeroContinue.tsx          풀블리드 히어로 (+온보딩 변형)
└─ BookRow.tsx               가로 표지 행 (진행 바/순위 뱃지 변형 지원)
```

- 이 파일들은 **새 토큰만** 쓴다: `useTheme()` · `typeScale` · `sans` · `spacing` · `radius`.
  레거시 `colors`/`type`/`fonts` import 금지 — 홈이 호환 레이어 탈출 1호 화면이다.
- 헤더 종 아이콘은 탭 레이아웃(`app/(tabs)/_layout.tsx`)의 `headerRight`로 추가.

## API 계약 (백엔드 서브프로젝트)

백엔드(`project-bookey-backend`)에 추가 — 별도 스펙/계획 사이클로 진행:

| 엔드포인트 | 응답 | 비고 |
|---|---|---|
| `GET /api/v1/banners` | `BannerView[]` — `id, title, subtitle?, imageUrl?, bgColor?, linkUrl?, sortOrder` | 서버가 기간(startsAt~endsAt) 내 활성만 정렬 반환. 인증 불필요 |
| `GET /api/v1/books/popular?size=20` | `PopularBookView[]` — `book: BookSummary` + `savedCount` | 서재 담김 수 집계 순. 집계 캐시 허용 |
| `GET /api/v1/books/recommended?size=20` | `BookSummary[]` | 에디터 픽, sortOrder 순 |

- 배너·에디터 픽 관리(생성·수정·기간·정렬)는 관리자 API + 백오피스(`project-bookey-admin`)
  화면이 필요하다. 이번 스코프는 **백엔드 공개 조회 + 관리자 관리 API까지**, 백오피스 화면은
  후속 작업으로 남긴다.
- **구현 순서**: ① 백엔드 API → ② 앱 `npm run types` 재생성, `types.ts`에 별칭(`Banner` 등)
  추가, `endpoints.ts`에 `bannerApi` 추가·`bookApi` 확장 → ③ 홈 화면 구현.
  앱 코드는 항상 생성 타입만 쓴다(손으로 필드 작성 금지 — 저장소 규칙).

## 상태 · 엣지 케이스

- **행 단위 독립성**: 행마다 자기 react-query 쿼리. 로딩 = 표지 스켈레톤, 오류 = 행 숨김,
  빈 = 행 숨김. 배너 서버 오류가 나머지 홈을 막지 않는다 (부분 실패 허용).
- **히어로**: 첫 로드 스켈레톤 → 데이터 도착 시 교체. READING 0권 = 온보딩 히어로.
- **당겨서 새로고침**: 모든 홈 쿼리 리페치.
- **다크/라이트**: 토큰 기반. 히어로·배너는 이미지 위 스크림 영역이라 두 모드 동일하게
  어둡다(OTT 관례). 나머지 행 배경·텍스트는 모드를 따른다.
