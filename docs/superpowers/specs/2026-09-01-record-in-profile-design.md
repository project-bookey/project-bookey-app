# 기록 탭 프로필 통합 — 설계 문서

2026-09-01 · 브레인스토밍 세션에서 사용자와 함께 결정

## 목표

'기록' 탭(스트릭·90일 히트맵·누적 통계)을 없애고 그 내용을 프로필 탭의 '내 서재' 카드
바로 아래에 **한 카드로 통합**한다. 탭은 홈/서재/모임/프로필 4개가 된다. OTT 리디자인의
"남은 화면" 목록에서 기록 화면이 빠지고, 백로그의 "히트맵 램프 팔레트 파생"을 함께 해소한다.

## 결정 요약

| 항목 | 결정 | 근거 |
|---|---|---|
| 기록 탭 | 삭제 (4탭) | 통계는 조회형 화면이라 프로필과 성격이 맞고, OTT 앱 관례처럼 탭이 단순해짐 |
| 배치 형태 | '기록' 카드 하나로 통합 | 프로필의 카드 단위 구성('내 서재' 카드)과 결이 맞고 화면이 덜 길어짐 |
| 위치 | '내 서재' 카드 바로 아래 | 사용자 지정 |
| 정보 유지 | 기록 탭 내용 전부 유지 | 스트릭 3종 · 히트맵+범례 · 누적 3종 — 요약이 아니라 이동 |
| 히트맵 색 | 테마 악센트에서 파생 | 파란색 하드코딩은 OTT 틸·라이트 모드와 충돌. 백로그 항목 해소 |

## '기록' 카드 — `app/(tabs)/profile.tsx` (수정)

'내 서재' 카드와 '재촉 톤' 섹션 사이에 추가. 카드 내부 구성(위→아래):

1. **아이브로** `기록`
2. **스트릭 행**: 현재 스트릭 · 최장 스트릭 · 이번 주 — 기존 기록 탭의 StatCell 3개
   + 세로 헤어라인 구분. 프로필의 `CountCell`과 같은 숫자 강조 스타일.
3. **90일 히트맵**: 주 단위 열로 쌓는 각진 칸(기존 Heatmap 로직 그대로 이식) + 우하단
   적음/많음 범례.
4. **헤어라인** 아래 **누적**: 총 독서시간 · 오늘 · 기록한 날 — 기존 `KeyValue` 로컬
   프리미티브 재사용.

데이터는 기존과 동일: `statsApi.summary(90)`, 쿼리 키 `['stats', 90]`.

- **로딩 중**: 기록 카드 자체를 렌더하지 않는다(스피너 없음). 내 서재 카드가 이미
  `?? 0` 폴백으로 즉시 렌더되는 것과 균형을 맞춰, 로드되면 카드가 나타난다.
- **실패 시**: 카드는 유지하고 안에 캡션 한 줄 "통계를 불러오지 못했습니다."

## 히트맵 램프 — 테마 파생

- 빈 칸(기록 없음): `colors.line`
- 채움 4단계: `colors.accent` + 알파 25% / 50% / 75% / 100% (hex 알파 접미사 `40`,
  `80`, `BF`, 없음). 팔레트가 hex 6자리(`#1FC7A8`/`#0E9F85`)이므로 접미사 방식이 성립한다.
- 범례도 같은 5단계를 쓴다. 다크·라이트 모두 팔레트에서 자동 파생 — 하드코딩 색 제거.

## 테마 인식

- 프로필은 이미 테마 인식(수동 테마 전환 스펙) — 이식하는 히트맵·스탯 행도 로컬
  프리미티브 방식을 따른다: 정적 `StyleSheet`는 레이아웃만, 색은 `useTheme()` 인라인 주입.
- 레거시 `colors`(다크 고정 호환 레이어)·`ui.tsx` 의존을 가져오지 않는다.
